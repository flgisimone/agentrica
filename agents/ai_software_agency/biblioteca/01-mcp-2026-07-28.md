# Model Context Protocol, specifica 2026-07-28

Fonte: mcp-spec · Versione: 2026-07-28 · Verificata il: 2026-11-19 · Da ricontrollare entro: 2027-02-19 · Ruoli: AISA-02, AISA-04, AISA-06, AISA-09, AISA-12

## Nozione
La revisione corrente della specifica MCP è la 2026-07-28 (la precedente è la 2025-11-25). Le novità principali: il protocollo diventa senza stato, senza la stretta di mano initialize; ogni richiesta porta versione del protocollo e capacità del client in _meta, e il server deve offrire server/discover per dichiarare versioni e capacità. Le sessioni del trasporto Streamable HTTP e l'intestazione Mcp-Session-Id spariscono. Le richieste dal server al client (elicitation, sampling, roots) sono sostituite dal modello Multi Round-Trip Requests: il server restituisce un risultato con resultType «input_required» e il client ripete la richiesta con le risposte. Ogni risultato ha un resultType obbligatorio. I task diventano un'estensione ufficiale.

Roots, Sampling e Logging sono deprecati, con una finestra di almeno dodici mesi prima della rimozione; ping e logging/setLevel sono rimossi.

## Come si applica
- Prima di progettare o rivedere un server o un client MCP, verifica quale revisione della specifica supporta l'SDK in uso: le API dell'SDK possono essere indietro rispetto alla specifica.
- Non introdurre funzioni nuove basate su Roots, Sampling o Logging; per i log di un server stdio usa stderr.
- Una funzione che chiede dati all'utente durante una chiamata (elicitation) va riletta alla luce di Multi Round-Trip Requests quando il progetto passa alla 2026-07-28.
- Nei rilievi cita la revisione della specifica (es. «MCP 2026-07-28»).
