# Model Context Protocol, specification 2026-07-28

Source: mcp-spec · Version: 2026-07-28 · Verified on: 2026-11-19 · Recheck by: 2027-02-19 · Roles: AISA-02, AISA-04, AISA-06, AISA-09, AISA-12

## Notion
The current revision of the MCP specification is 2026-07-28 (the previous one is 2025-11-25). The main changes: the protocol becomes stateless, without the initialize handshake; every request carries the protocol version and the client capabilities in _meta, and the server must offer server/discover to declare versions and capabilities. Sessions of the Streamable HTTP transport and the Mcp-Session-Id header go away. Requests from server to client (elicitation, sampling, roots) are replaced by the Multi Round-Trip Requests model: the server returns a result with resultType «input_required» and the client repeats the request with the answers. Every result has a mandatory resultType. Tasks become an official extension.

Roots, Sampling and Logging are deprecated, with a window of at least twelve months before removal; ping and logging/setLevel are removed.

## How it applies
- Before designing or reviewing an MCP server or client, check which revision of the specification the SDK in use supports: the SDK APIs may lag behind the specification.
- Do not add new features based on Roots, Sampling or Logging; for the logs of a stdio server use stderr.
- A feature that asks the user for data during a call (elicitation) must be reviewed in the light of Multi Round-Trip Requests when the project moves to 2026-07-28.
- In findings, cite the revision of the specification (e.g. «MCP 2026-07-28»).
