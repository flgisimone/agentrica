# Piano di Agentrica

Agentrica è un server MCP con agenti IA organizzati in reparti (le agenzie di `agents/`), da usare nei propri progetti; ogni agente ha un nome in codice. Il progetto è partito da un sito che la presentava come una società (F0–F27) ed è diventato, da F28, uno strumento per sviluppatori: il server MCP rende gli agenti utilizzabili nei progetti di chiunque e il sito li presenta.

Questo piano raccoglie le decisioni prese e le fasi di lavoro, una per file.

## Come si lavora a una fase

- Ogni fase ha un file `NN-nome.md` con obiettivo, stato, agenzie, backlog, criteri di accettazione e, a fine fase, «Fatto», «Verifiche» e «Rilievi aperti» (modello: [00-base.md](00-base.md)).
- Si lavora su un branch `fase/fN-nome`, partendo da `develop`; le correzioni fuori fase su `fix/nome`.
- Le «proposte da confermare» nei file di fase si decidono con l'utente all'apertura di ciascuna.
- La fase si chiude con la procedura di CONVENTIONS §13.7: piano aggiornato, controlli, **un'unica conferma dell'utente**, poi commit, merge in `develop`, push, `tokensave sync` e `/clear`.
- Il merge in `main` è un rilascio a parte, solo su richiesta dell'utente (CONVENTIONS §13.8).

## Glossario

«Agentrica» (il progetto: server MCP, catalogo e sito), «Reparto» (un'agenzia: AIBPD, AICA, AIPCA, AISA, AIWDA), «Agente» (un ruolo di un reparto), «Nome in codice» (es. AISA-02 · ALTAIR), «Direttore» (l'agente 01 di ogni reparto), «Biografia» (la pagina di un agente, ricavata dal suo file), «Catalogo» (i dati di reparti e agenti letti da `agents/`), «Pagina del reparto», «Pagina dell'agente», «Squadra» (gli agenti scelti da un utente per il suo MCP con `--agents`), «Biblioteca» (le schede di nozioni recenti di un reparto), «Scheda» (una nozione con fonte, versione e date), «Ciclo di studio» (rilevatore, sessione di studio e revisione che aggiornano la biblioteca).

Parole inglesi ammesse nei testi italiani (CONVENTIONS §3, F31), elenco chiuso:

- **Sviluppo**: audit, backlog, branch, build, bundle, CI, commit, deploy, flag, helper, id, lint, merge, MCP, mock, payload, prompt, provenance, push, route, runtime, server, test, token, tool, trusted publisher, typecheck, UI, UX, workflow, Definition of Done.
- **Web e strumenti**: account, file, on-premise, privacy, design, design system, download, end-to-end, focus, footer, header, hero, issue e PR (di GitHub), login, online, offline, plugin, responsive, alert (componente), backend, backup, badge, banner, browser, bug, cache, card, chat, cloud, container, cookie, dashboard, endpoint, fixture, form, framework, frontend, hosting, layout, link, log, password, placeholder, query, rendering, repository, screenshot, script, seed, select, snapshot, stack, tenant, tooltip, viewport.
- **Gestione**: budget, business case, feedback, freemium, marketing, partner, pipeline, policy, pricing, roadmap, target, team, user story.
- **Sicurezza**: advisory, backdoor, brute force, data breach, DoS, exploit, firewall, malware, password spraying, pentest, phishing, playbook, ransomware, rollback, scanner, social engineering, spyware, staging, threat model.
- **Nomi propri**: reparti, sigle, stelle, titoli dei ruoli, prodotti e standard.

Il resto si traduce: output → risultato, report → resoconto (resta nel nome dei file `report-*.md`), handoff → passaggio di consegne, asset → risorse, task → attività, input → dati in ingresso, review → revisione, gap → lacuna, brief → sintesi, feed → flusso, scope → perimetro, finding → rilievo, feature → funzione, issue → segnalazione (salvo le issue di GitHub).
